# Трекер полезных привычек (Backend)

> Бэкенд-часть SPA веб-приложения для приобретения полезных привычек и искоренения плохих, разработанная по мотивам книги Джеймса Клира «Атомные привычки». Проект контейнеризирован и разворачивается автоматически с помощью CI/CD.

---
## 🛠 Стек технологий
- **Backend:** Python 3.11+ / Django / Django REST Framework (DRF)
- **База данных & Кэш:** PostgreSQL / Redis
- **Фоновые задачи:** Celery + Celery Beat (планировщик напоминаний)
- **Веб-сервер & Контейнеры:** Nginx / Docker / Docker Compose
- **CI/CD:** GitHub Actions (деплой на удаленный сервер)
- **Линтеры и тесты:** Flake8 / Black / Isort / Coverage

---

## Особенности проекта
-  **CORS настроен:** Разрешенные домены вынесены в конфигурацию (`CORS_ALLOW_ALL_ORIGINS = True`).
-  **Авторизация:** Кастомная авторизация пользователей по Email и JWT-токенам.
-  **Валидаторы:** Реализованы 5 жестких бизнес-валидаторов для моделей привычек.
-  **Telegram Интеграция:** Автоматическая отправка напоминаний через бота каждую минуту с помощью Celery Beat.
-  **Покрытие тестами:** Покрытие кода составляет **>80%** (включая асинхронные задачи). Для тестов автоматически разворачивается изолированная БД `sqlite3`.
-  **Документация:** Интерактивные эндпоинты Swagger и ReDoc с поддержкой Bearer-авторизации.

## Локальная установка и запуск

### Способ 1: Запуск в окружении разработки (Poetry)

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/sergeydomrachev30-source/Course_work_5.git
   cd Course_work_5
   ```

2. **Настройте переменные окружения:**
   ```bash
   cp .env.template .env
   ```
   *Заполните в `.env` параметры подключения к вашей локальной PostgreSQL, Redis и токен `TELEGRAM_TOKEN`.*

3. **Установите зависимости и активируйте окружение:**
   ```bash
   poetry install
   poetry shell
   ```

4. **Примените миграции и запустите сервер:**
   ```bash
   python manage.py migrate
   python manage.py runserver
   ```

5. **Запустите Celery в отдельных терминалах:**
   ```bash
   # Запуск воркера
   celery -A config worker --loglevel=info
   # Запуск планировщика задач (Beat)
   celery -A config beat --loglevel=info
   ```

## Контейнеризация (Docker Compose)

Проект полностью подготовлен для сборки и запуска всех 
сервисов одной командой. Архитектура включает отдельные изолированные контейнеры 
для **Django**, **PostgreSQL**, **Redis**, **Celery Worker**, **Celery Beat** и **Nginx** 
(в качестве reverse-proxy).

**Запуск проекта локально в Docker:**
1. Убедитесь, что файл `.env` создан и заполнен.
2. Выполните команду:
   ```bash
   docker-compose up --build
   ```
Приложение автоматически проведет миграции, соберет статику и запустит веб-сервер Nginx на порту `80`.

## Настройка CI/CD и автоматического деплоя

В проекте настроен пайплайн автоматизации на базе **GitHub Actions** (`.github/workflows/main.yml`). 

### Как работает пайплайн:
1. **Тестирование и линтинг:** При пуше или pull-request в ветку автоматический раннер запускает тесты (`coverage`) и проверяет стиль кода линтером (`flake8`).
2. **Проверка сборки:** Проверяется успешность сборки Docker-образов.
3. **Автоматический деплой:** При успешном прохождении всех шагов пайплайн подключается к удаленному серверу Yandex Cloud по SSH, обновляет кодовую базу из репозитория и перезапускает проект через Docker Compose.

### Инструкция по настройке деплоя на Yandex Cloud:

1. **Подготовка сервера:**
   - Создайте виртуальную машину в **Yandex Cloud** (Ubuntu Server) — текущий рабочий IP: `158.160.235.91`.
   - Установите на сервер Docker и Docker Compose.
   - Сгенерируйте пару SSH-ключей. Добавьте публичный ключ в `~/.ssh/authorized_keys` на сервере.

2. **Настройка GitHub Secrets:**
   Для работы пайплайна перейдите в свой репозиторий GitHub: **Settings -> Secrets and variables -> Actions** и добавьте следующие секреты (`Repository secrets`):
   - `SSH_HOST` — IP-адрес вашей виртуальной машины (`158.160.235.91`).
   - `SSH_USER` — Имя пользователя для подключения (например, `ubuntu` или `yc-user`).
   - `SSH_KEY` — Ваш приватный SSH-ключ (содержимое файла `id_rsa`).
   - `ENV_FILE` — Полное содержимое вашего боевого файла `.env` со всеми паролями, секретным ключом Django, токенами 
   - Telegram и настройками БД.

> **Важное напоминание (Yandex Cloud):** Во избежание непредвиденных списаний средств со стартового баланса, включайте 
> виртуальную машину только на период разработки и проверки задания наставником. После утверждения работы остановите или удалите ВМ.
